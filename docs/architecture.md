# MVP architecture and trust boundaries

`src/core/sessions.js` owns comparison identity, exact commit targets, status transitions, startup cancellation, cleanup ordering, and feedback provenance. Its repository, web, and storage ports are injected. It contains no DOM, iframe, HTTP, or container operations. Feedback geometry uses normalized coordinates and generic tool names (`pen`, `region`, `arrow`), so another adapter can interpret the same records.

`src/adapters/git.js` resolves refs as commits with argument arrays and `--end-of-options`. It ignores global/system Git configuration and inherited `GIT_*` variables, disables hooks, clones only committed objects into a private bare repository without hardlinks, then creates detached left/right worktrees there. It never adds a worktree entry to the user's repository or executes checkout code. Removing the owned session directory removes the private repository and its worktree metadata together; no broad `git worktree prune` is needed. Host Git object parsing and cloning are trusted operations, so repository size and Git vulnerabilities are outside container protection.

`src/adapters/docker-web.js` implements web launching/readiness/embedding checks behind the web port. `public/capture.js` is the browser-side capture portion of the Web adapter. Docker creates each target with deterministic names and labels containing both data-directory ownership and session identity. It exposes each app only on loopback on a separate port. A read-only worktree is copied into bounded ephemeral `/app` storage; the `.git` pointer is removed from that copy. Installation and execution both happen as the unprivileged container user. Container capabilities are dropped, privilege escalation is disabled, and the root filesystem is read-only. See the [Docker run reference](https://docs.docker.com/reference/cli/docker/container/run/) and [localhost port publishing behavior](https://docs.docker.com/engine/network/port-publishing/).

The adapter does not forward the host environment, mount a package cache, accept arbitrary Docker flags, build repository Dockerfiles, or invoke a host install/start command. Container images must be pre-pulled and are part of the operator's trust decision. Outbound container networking is available for package installation, so code may contact internet, LAN, and Docker-reachable host services. For malicious code, use a dedicated VM with an egress policy. Docker restrictions limit ordinary process and filesystem damage; they are not a claim of hardware isolation.

The Node HTTP server binds `127.0.0.1`, validates the Host and Origin, rejects cross-site requests, and requires a per-server unpredictable token plus JSON content type for mutations. Other websites and the untrusted app origins cannot read this token through browser same-origin protections. The UI has a restrictive CSP and cannot itself be framed. No CORS policy grants access to app origins. This protects browser-initiated local API requests; local OS users/processes with host access are trusted. The tool has no remote authentication and must not be reverse-proxied to a shared network.

The sandboxed app iframes have independent browser state. Capturing uses browser-mediated `getDisplayMedia`, not app-injected JavaScript or cross-origin DOM access. [Capture Handle](https://developer.chrome.com/docs/web-platform/capture-handle) identifies the current GitArena tab before its stream is cropped to the selected iframe. Other tabs, windows, and monitors are rejected. All tracks stop in a `finally` block even on failure. A snapshot is immutable; annotations are layered on it as SVG while editing and persisted as geometry with free text. Capture is supported on desktop Chromium browsers with these APIs; live comparison and saved feedback viewing do not require screen-capture support.

A session journal is written before worktrees or containers are created. Partial startup waits for both launch attempts to settle before cleanup, including when one fails or the user cancels. Cleanup removes labeled containers first, then owned directories; a Docker failure preserves the journal/worktrees and blocks another launch. Runtime health checks stop the session if an application exits. Graceful shutdown cancels startup and stops running sessions. An exclusive data-directory PID lock prevents simultaneous recovery by multiple servers. On restart after abrupt termination, journals marked starting/running/stopping/cleanup-failed are cleaned before the server accepts requests. Recovery requires access to the same Docker daemon. No cleanup runs while the server is dead; containers may continue until restart. Feedback and completed session metadata are retained independently of ephemeral resources.

Storage uses private JSON files and same-directory atomic rename, with bounded request sizes and validated PNG metadata and geometry. It is designed for a single local user, one comparison at a time. It is not a database, distributed scheduler, remote repository fetch service, or process supervisor. Saved context contains both exact SHAs and the original refs, repository path, side, and session ID. Reopening a saved snapshot never relaunches code or accesses a formerly assigned app port.
